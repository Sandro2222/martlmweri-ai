# MartlweraAI — ქართული მართლწერის შემმოწმებელი (Groq / openai/gpt-oss-120b)

გაკეთებულია ალექსანდრე ჯავარაშვილის მიერ.

ეს ვერსია იყენებს Groq-ის AI მოდელს მართლწერის შესამოწმებლად და გასასწორებლად. **API გასაღები ინახება მხოლოდ სერვერზე** (`.env` ფაილში) და არასდროს იგზავნება ბრაუზერში — ანუ საიტის სტუმრები ვერასდროს ნახავენ ან მოიპარავენ თქვენს გასაღებს გვერდის კოდში ჩახედვით.

### რატომ `openai/gpt-oss-120b` და არა `llama-3.1-8b-instant`

თავდაპირველად ეს პროექტი იყენებდა `llama-3.1-8b-instant`-ს — ეს არის ძალიან პატარა და სწრაფი მოდელი (8 მილიარდი პარამეტრი), რომელიც კარგადაა ოპტიმიზირებული ინგლისურისთვის, მაგრამ სუსტია ისეთი „დაბალრესურსიანი" ენებისთვის, როგორიც ქართულია — ხშირად ვერც აშკარა შეცდომებს ამჩნევს. გარდა ამისა, Groq-მა ეს მოდელი გამოაცხადა მოძველებულად (deprecated) და 2026 წლის 16 აგვისტოს გამორთავს.

ახლა ნაგულისხმევად გამოიყენება **`openai/gpt-oss-120b`** — Groq-ის ყველაზე ძლიერი ზოგადდანიშნულების მოდელი (120 მილიარდი პარამეტრი, MoE არქიტექტურა), რომელიც ასევე უფასო ტიერზეა ხელმისაწვდომი და გაცილებით უკეთესად უმკლავდება ქართულ ტექსტს. სისტემურ პრომფტშიც დამატებულია კონკრეტული მაგალითები (მათ შორის ზუსტად თქვენი „შეურაცხყოფა"-ტიპის შემთხვევა), რომ მოდელმა ასეთი დახვეწილი არევები არ გამოტოვოს.

**გაფრთხილება:** არც ერთი უფასო ან იაფი მოდელი ვერ მოგცემთ 100%-იან სიზუსტეს ქართულზე — ეს დაბალრესურსიანი ენაა ტრენინგის მონაცემებში, ამიტომ ხანდახან შეცდომები მაინც შეიძლება გამოგრჩეთ. თუ მაქსიმალური სიზუსტე გჭირდებათ, უფრო დიდი/ძვირი მოდელები (მაგ. Claude) მნიშვნელოვნად უკეთეს შედეგს იძლევა.

### დამატებითი გაუმჯობესებები

- სისტემურ პრომფტში დამატებულია მითითებები დეფისიანი შედგენილი სიტყვების შესახებ (მაგ. „ერთერთი" → „ერთ-ერთი", „პრემიერმინისტრი" → „პრემიერ-მინისტრი").
- დამატებულია მკაცრი წესი, რომ მოდელმა არასდროს „გამოიგონოს" ახალი, არარსებული სიტყვა იმის ნაცვლად, რომ სიტყვა უცვლელად დატოვოს, თუ არ არის დარწმუნებული სწორ ვარიანტში (ეს გამოსწორებულია იმ შემთხვევის შემდეგ, როცა „პრემიერმინისტრი" შეცდომით გადაკეთდა „პრემიერმაინისტრი"-დ).
- სერვერზე დამატებულია მარტივი დაცვის მექანიზმი: თუ მოდელი ტექსტს სიგრძით 25%-ზე მეტად შეცვლის (რაც ჩვეულებრივი მართლწერის გასწორებისთვის არანორმალურია), პასუხი უარყოფილია და მომხმარებელს სთხოვს ხელახლა სცადოს, ნაცვლად იმისა, რომ არასანდო შედეგი გამოსცეს.

## რატომ არის გასაღები დაცული

- ბრაუზერში (`public/index.html`-ში) გასაღები საერთოდ არ ჩანს — ის მხოლოდ `server.js`-შია, სერვერის მხარეს.
- ბრაუზერი მხოლოდ თქვენს სერვერს (`/api/check`) ესაუბრება, სერვერი კი — Groq-ს. მომხმარებელს არასდროს აქვს პირდაპირი წვდომა Groq API-ზე.
- `.gitignore` ფაილი უზრუნველყოფს, რომ `.env` (სადაც რეალური გასაღები წერია) ვერასდროს აიტვირთება GitHub-ზე ან სხვა საჯარო რეპოზიტორიზე, თუ პროექტს git-ით მართავთ.
- ჩამატებულია მარტივი **rate limiting** (`server.js`-ში, ცვლადები `MAX_REQUESTS` / `WINDOW_MS`) — ზღუდავს თითო IP-დან წუთში მოთხოვნების რაოდენობას, რომ შემთხვევით ან განზრახ ვინმემ ვერ „დაგლიოთ" თქვენი Groq ლიმიტი/ბალანსი საიტზე ბევრი მოთხოვნით.

**მნიშვნელოვანი:** არასდროს ატვირთოთ `.env` ფაილი დისკზე საჯაროდ ხელმისაწვდომ ადგილას (მაგ. GitHub-ის საჯარო რეპოზიტორიში, ან სტატიკური ფაილების საქაღალდეში, საიდანაც ის პირდაპირ URL-ით იქნება წამოსაღები). `.env` უნდა დარჩეს მხოლოდ იმ სერვერზე, სადაც `node server.js` გაქვთ გაშვებული.

## რა შედის პროექტში

- `lib/checker.js` — მთავარი ლოგიკა: Groq-ის გამოძახება, პასუხის დამუშავება და „hallucination guard" (იხ. ქვემოთ). საერთოა ლოკალური სერვერისა და Vercel-ისთვის.
- `server.js` — Node.js/Express სერვერი **ლოკალური** გაშვებისთვის. შეიცავს rate limiting-საც.
- `api/check.js` — იგივე endpoint **Vercel-ის** serverless ფუნქციის სახით.
- `public/index.html` — საიტის წინა მხარე (ტექსტის ველი, „შემოწმება" ღილაკი, შედეგის ჩვენება ცვლილებების მონიშვნით).
- `test-guard.js` — ტესტები guard-ისთვის (`npm test`).
- `vercel.json` — Vercel-ის კონფიგურაცია.
- `package.json` — დამოკიდებულებები.
- `.env.example` — მაგალითი გარემოს ცვლადებისთვის.
- `.gitignore` — იცავს `.env`-ს შემთხვევითი გამოქვეყნებისგან.

## „Hallucination guard"

მოდელი ზოგჯერ სწორ სიტყვას ცვლიდა სრულიად სხვა სიტყვით (მაგ. `ადანაშაულებს` → `დასაშლელად`) — ეს არ არის მართლწერის შესწორება, არამედ ტექსტის გადაწერა. მხოლოდ პრომპტით ამის აკრძალვა არ არის საკმარისი, ამიტომ პასუხი კოდშივე მოწმდება:

- ტექსტი და მოდელის პასუხი ერთმანეთს ედრება **სიტყვა-სიტყვით**;
- თითოეული ცვლილებისთვის ითვლება Levenshtein-ის მანძილი — ნამდვილი ორთოგრაფიული შესწორება ყოველთვის მცირეა (1–2 ასო);
- ძალიან შორეული ჩანაცვლება, სიტყვის წაშლა ან დამატება **უარყოფილია** და ბრუნდება მომხმარებლის ორიგინალი სიტყვა.

ასე `საქემ` → `საქმეს` (2 ასო) რჩება, ხოლო `ადანაშაულებს` → `დასაშლელად` (9 ასო) უქმდება. ზღვარი რეგულირდება `editBudget()` ფუნქციაში (`lib/checker.js`).

## დაყენება და გაშვება ლოკალურად

1. საჭიროა [Node.js](https://nodejs.org) (ვერსია 18+).
2. პროექტის საქაღალდეში:

   ```
   npm install
   ```

3. დააკოპირეთ `.env.example` → `.env`:

   ```
   cp .env.example .env
   ```

   და ჩაწერეთ თქვენი რეალური Groq გასაღები:

   ```
   GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxx
   ```

4. გაუშვით სერვერი:

   ```
   npm start
   ```

5. გახსენით:

   ```
   http://localhost:3000
   ```

## Vercel-ზე გაშვება

პროექტი უკვე მომზადებულია Vercel-ისთვის: `api/check.js` არის serverless ფუნქცია, `public/` — სტატიკური საიტი.

1. შედით [vercel.com](https://vercel.com)-ზე GitHub ანგარიშით.
2. **Add New → Project** და აირჩიეთ თქვენი რეპოზიტორია.
3. **Framework Preset** — უნდა იყოს **Other**. `vercel.json`-ში უკვე წერია `"framework": null`, რაც სწორედ ამას ნიშნავს, ასე რომ ჩვეულებრივ ხელით შეცვლა საჭირო არაა.
4. **Output Directory** — **არაფერი** ჩაწეროთ (დატოვეთ ნაგულისხმევი). Vercel თავად ემსახურება `public/`-ს.
5. **Environment Variables** განყოფილებაში დაამატეთ:

   | Name | Value |
   | --- | --- |
   | `GROQ_API_KEY` | `gsk_...` (თქვენი რეალური გასაღები) |
   | `GROQ_MODEL` | `openai/gpt-oss-120b` (არასავალდებულო) |

6. **Deploy**.

შემდეგი push-ები `main`-ზე ავტომატურად განაახლებს საიტს.

### ხშირი შეცდომა: `No entrypoint found in output directory: "public"`

ორი განსხვავებული მიზეზი აქვს — შეამოწმეთ ორივე:

1. **მითითებული `outputDirectory`.** თუ `public` ხელით არის ჩაწერილი (`vercel.json`-ში ან Project Settings-ში), Vercel მას build-ის შედეგად მიიჩნევს. გამოსავალი: წაშალეთ — „Other" preset თავისით ემსახურება `public/`-ს.

2. **Express-ის ავტომატური ამოცნობა.** თუ შეცდომაში ჩამოთვლილია `app.js`, `index.js`, `server.js`, `src/index.js` და ა.შ., ესე იგი Vercel-მა პროექტი **Express**-ად ჩათვალა (რადგან `express` არის `dependencies`-ში) და სრულ Node სერვერს ეძებს. ჩვენთან `express` მხოლოდ ლოკალური გაშვებისთვისაა.

   გამოსავალი — `vercel.json`-ში:

   ```json
   { "framework": null }
   ```

   `null` ნიშნავს „Other"-ს და აუქმებს ავტომატურ ამოცნობას. თუ Project Settings-ში Framework Preset უკვე შენახულია როგორც „Express", შეცვალეთ **Other**-ით და გააკეთეთ **Redeploy**.

**შენიშვნა:** Vercel-ის serverless ინსტანციები დროებითია, ამიტომ `api/check.js`-ის rate limiter მხოლოდ ერთი „თბილი" ინსტანციის ფარგლებში მუშაობს. მკაცრი გლობალური ლიმიტისთვის დაგჭირდებათ საერთო საცავი (Vercel KV ან Upstash Redis).

### სხვა ვარიანტები

- **Render.com / Railway.app / Fly.io** — იქ `server.js` პირდაპირ გაეშვება (`npm start`); გასაღები ისევ Environment Variables პანელში ჩაიწერება.

ყველა შემთხვევაში წესი ერთია: **გასაღები არასდროს შედის კოდში ან git history-ში — ის ყოველთვის ცალკე, ჰოსტინგის საიდუმლო (secret) ცვლადების სისტემაში იწერება.**

## შენიშვნა ხარჯებზე

Groq-ის API ფასიანია გამოყენების მოცულობის მიხედვით (თუმცა Groq ხშირად სთავაზობს გულუხვ უფასო ლიმიტს/ტიერს — დეტალები შეამოწმეთ [console.groq.com](https://console.groq.com)-ზე). ჩამატებული rate limiting გეხმარებათ, რომ ვერავინ ბოროტად გამოიყენოს თქვენი გასაღები დიდი მოცულობის მოთხოვნებით.
