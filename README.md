# MartlweraAI — ქართული მართლწერის შემმოწმებელი (Google Gemini)

გაკეთებულია ალექსანდრე ჯავარაშვილის მიერ.

**API გასაღები ინახება მხოლოდ სერვერზე** (`.env` ფაილში) და არასდროს იგზავნება ბრაუზერში — ანუ საიტის სტუმრები ვერასდროს ნახავენ ან მოიპარავენ თქვენს გასაღებს გვერდის კოდში ჩახედვით.

## როგორ მუშაობს — ოთხი ფენა

მთავარი პრობლემა ის იყო, რომ მოდელი **ვერ ამჩნევდა** შეცდომებს. ამიტომ შემოწმება აღარ ეყრდნობა მხოლოდ მოდელს — ტექსტი გადის ოთხ ფენას:

1. **წესების ფენა** (`lib/rules.js`) — დეტერმინისტული, 100%-ით საიმედო შესწორებები: კლავიატურის განლაგების შეცდომები (ლათინური ასო ქართულ სიტყვაში: „მცხოვრებi" → „მცხოვრები") და დეფისიანი შედგენილი სიტყვები ყველა ბრუნვის ფორმაში („პრემიერმინისტრის" → „პრემიერ-მინისტრის"). აქ მოდელი საერთოდ არ მონაწილეობს, ამიტომ შეცდომა გამორიცხულია.

2. **ლექსიკონის ფენა** (`lib/dictionary.js`) — **ეს არის მთავარი გაუმჯობესება.** პროექტში ჩაშენებულია ქართული ენის ნამდვილი ლექსიკონი (Hunspell ფორმატი, ~143,000 ძირი + 1,798 აფიქსის წესი, MIT ლიცენზია). ყოველი სიტყვა მოწმდება ლექსიკონში — მათ შორის ბრუნვის, უღლების, პრეფიქსისა და სუფიქსის ფორმები. სიტყვები, რომლებიც ლექსიკონში ვერ მოიძებნა, გადაეცემა მოდელს **ცალკე სიის სახით**.

   ეს ცვლის ამოცანას: მოდელს აღარ ეკითხება „იპოვე შეცდომები" (რასაც ცუდად ართმევდა თავს), არამედ „ეს კონკრეტული სიტყვა საეჭვოა — რა არის სწორი ფორმა?" (რასაც კარგად ართმევს თავს).

3. **მოდელი** (`lib/providers.js`) — Google Gemini ასწორებს მონიშნულ სიტყვებს. ლექსიკონის სია გადაეცემა როგორც **მინიშნება და არა ბრძანება**: ლექსიკონი ვერ შეიცავს ყველა გვარს, ქალაქის სახელსა და იშვიათ ფორმას, ამიტომ მოდელს პირდაპირ ეუბნება, რომ სწორი სიტყვა უცვლელად დატოვოს.

4. **დაცვის ფენა (guard)** (`lib/checker.js`) — ბოლო სიტყვა ყოველთვის კოდს რჩება: მოდელის ყოველი ცვლილება მოწმდება და ძალიან შორეული ჩანაცვლება უქმდება (იხ. „Hallucination guard" ქვემოთ).

### რატომ Gemini და არა Groq

პროექტი მუშაობს ორივესთან, მაგრამ ნაგულისხმევია **Gemini**:

- **სიზუსტე** — ტესტებზე Gemini-მ **0 ცრუ გასწორება** დაუშვა (Groq-ს 1 ჰქონდა: სწორ „კაცია"-ს „კაცი"-დ ცვლიდა).
- **ლიმიტი** — Groq-ის უფასო ტიერს აქვს 8,000 ტოკენი/წუთში, ხოლო სისტემური პრომფტი დაახლოებით 3,100 ტოკენია; ანუ წუთში მხოლოდ ~2 შემოწმება გამოდიოდა, შემდეგ კი შეცდომა 429. Gemini-ს ეს ზღვარი არ აქვს.

Groq კვლავ მუშა მდგომარეობაშია — `.env`-ში `PROVIDER=groq` საკმარისია გადასართავად.

**გაფრთხილება:** 100%-იან სიზუსტეს არც ერთი მოდელი ვერ მოგცემთ ქართულზე — ეს დაბალრესურსიანი ენაა. ლექსიკონის ფენა მნიშვნელოვნად აუმჯობესებს შეცდომების **აღმოჩენას**, მაგრამ იშვიათი შეცდომები მაინც შეიძლება გამოგრჩეთ.

## რატომ არის გასაღები დაცული

- ბრაუზერში (`public/index.html`-ში) გასაღები საერთოდ არ ჩანს — ის მხოლოდ `server.js`-შია, სერვერის მხარეს.
- ბრაუზერი მხოლოდ თქვენს სერვერს (`/api/check`) ესაუბრება, სერვერი კი — Gemini-ს. მომხმარებელს არასდროს აქვს პირდაპირი წვდომა AI API-ზე.
- `.gitignore` ფაილი უზრუნველყოფს, რომ `.env` (სადაც რეალური გასაღები წერია) ვერასდროს აიტვირთება GitHub-ზე ან სხვა საჯარო რეპოზიტორიზე, თუ პროექტს git-ით მართავთ.
- ჩამატებულია მარტივი **rate limiting** (`server.js`-ში, ცვლადები `MAX_REQUESTS` / `WINDOW_MS`) — ზღუდავს თითო IP-დან წუთში მოთხოვნების რაოდენობას, რომ შემთხვევით ან განზრახ ვინმემ ვერ „დაგლიოთ" თქვენი API ლიმიტი საიტზე ბევრი მოთხოვნით.

**მნიშვნელოვანი:** არასდროს ატვირთოთ `.env` ფაილი დისკზე საჯაროდ ხელმისაწვდომ ადგილას (მაგ. GitHub-ის საჯარო რეპოზიტორიში, ან სტატიკური ფაილების საქაღალდეში, საიდანაც ის პირდაპირ URL-ით იქნება წამოსაღები). `.env` უნდა დარჩეს მხოლოდ იმ სერვერზე, სადაც `node server.js` გაქვთ გაშვებული.

## რა შედის პროექტში

- `lib/checker.js` — მთავარი ლოგიკა: ფენების გაერთიანება, პასუხის დამუშავება და „hallucination guard". საერთოა ლოკალური სერვერისა და Vercel-ისთვის.
- `lib/rules.js` — დეტერმინისტული წესები (კლავიატურის განლაგება, დეფისები).
- `lib/dictionary.js` — ქართული ლექსიკონის კითხვა და სიტყვის შემოწმება (Hunspell აფიქსების ჩათვლით).
- `lib/providers.js` — Gemini და Groq პროვაიდერები ერთი საერთო ინტერფეისით.
- `data/ka.dic`, `data/ka.aff` — ქართული ლექსიკონი (MIT, იხ. `data/ka.license`).
- `server.js` — Node.js/Express სერვერი **ლოკალური** გაშვებისთვის. შეიცავს rate limiting-საც.
- `api/check.js` — იგივე endpoint **Vercel-ის** serverless ფუნქციის სახით.
- `public/index.html` — საიტის წინა მხარე (ტექსტის ველი, „შემოწმება" ღილაკი, შედეგის ჩვენება ცვლილებების მონიშვნით).
- `test-guard.js`, `test-rules.js`, `test-dictionary.js` — ტესტები (`npm test`, 65 ტესტი, ინტერნეტის გარეშე).
- `bench/` — სიზუსტის გასაზომი ბენჩმარკი (`npm run bench` — საჭიროებს API გასაღებს).
- `vercel.json` — Vercel-ის კონფიგურაცია.
- `package.json` — დამოკიდებულებები.
- `.env.example` — მაგალითი გარემოს ცვლადებისთვის.
- `.gitignore` — იცავს `.env`-ს შემთხვევითი გამოქვეყნებისგან.

## სიზუსტის გაზომვა

`npm run bench` ამოწმებს 16 შემთხვევას და აჩვენებს სამ რიცხვს: **FIXED** (გასწორებული შეცდომები), **MISSED** (გამოტოვებული) და **BROKE** (სწორი ტექსტი, რომელიც შეცდომით შეიცვალა).

ბოლო შედეგი (`gemini-3.5-flash`): **12/13 გასწორებული (92%), 0 ცრუ გასწორება.**

## „Hallucination guard"

მოდელი ზოგჯერ სწორ სიტყვას ცვლიდა სრულიად სხვა სიტყვით (მაგ. `ადანაშაულებს` → `დასაშლელად`) — ეს არ არის მართლწერის შესწორება, არამედ ტექსტის გადაწერა. მხოლოდ პრომპტით ამის აკრძალვა არ არის საკმარისი, ამიტომ პასუხი კოდშივე მოწმდება:

- ტექსტი და მოდელის პასუხი ერთმანეთს ედრება **სიტყვა-სიტყვით**;
- თითოეული ცვლილებისთვის ითვლება Levenshtein-ის მანძილი — ნამდვილი ორთოგრაფიული შესწორება ყოველთვის მცირეა (1–2 ასო);
- ძალიან შორეული ჩანაცვლება, სიტყვის წაშლა ან დამატება **უარყოფილია** და ბრუნდება მომხმარებლის ორიგინალი სიტყვა.

ასე `საქემ` → `საქმეს` (2 ასო) რჩება, ხოლო `ადანაშაულებს` → `დასაშლელად` (9 ასო) უქმდება. ზღვარი რეგულირდება `editBudget()` ფუნქციაში (`lib/checker.js`).

## დაყენება და გაშვება ლოკალურად

1. საჭიროა [Node.js](https://nodejs.org) (ვერსია 18+).
2. პროექტის საქაღალდეში:

   ```
   npm install
   ```

3. დააკოპირეთ `.env.example` → `.env`:

   ```
   cp .env.example .env
   ```

   და ჩაწერეთ თქვენი რეალური Gemini გასაღები (უფასოდ მიიღებთ [aistudio.google.com/apikey](https://aistudio.google.com/apikey)-ზე):

   ```
   GEMINI_API_KEY=თქვენი_გასაღები
   ```

4. გაუშვით სერვერი:

   ```
   npm start
   ```

5. გახსენით:

   ```
   http://localhost:3000
   ```

## Vercel-ზე გაშვება

პროექტი უკვე მომზადებულია Vercel-ისთვის: `api/check.js` არის serverless ფუნქცია, `public/` — სტატიკური საიტი.

1. შედით [vercel.com](https://vercel.com)-ზე GitHub ანგარიშით.
2. **Add New → Project** და აირჩიეთ თქვენი რეპოზიტორია.
3. **Framework Preset** — უნდა იყოს **Other**. `vercel.json`-ში უკვე წერია `"framework": null`, რაც სწორედ ამას ნიშნავს, ასე რომ ჩვეულებრივ ხელით შეცვლა საჭირო არაა.
4. **Output Directory** — **არაფერი** ჩაწეროთ (დატოვეთ ნაგულისხმევი). Vercel თავად ემსახურება `public/`-ს.
5. **Environment Variables** განყოფილებაში დაამატეთ:

   | Name | Value |
   | --- | --- |
   | `GEMINI_API_KEY` | თქვენი რეალური Gemini გასაღები |
   | `GEMINI_MODEL` | `gemini-3.5-flash` (არასავალდებულო) |

   **მნიშვნელოვანი:** გასაღები ჩაწერეთ Vercel-ის პანელში ხელით. არასდროს ჩააკოპიროთ ის კოდში ან რომელიმე ფაილში, რომელიც GitHub-ზე აიტვირთება.

6. **Deploy**.

შემდეგი push-ები `main`-ზე ავტომატურად განაახლებს საიტს.

### ხშირი შეცდომა: `No entrypoint found in output directory: "public"`

ორი განსხვავებული მიზეზი აქვს — შეამოწმეთ ორივე:

1. **მითითებული `outputDirectory`.** თუ `public` ხელით არის ჩაწერილი (`vercel.json`-ში ან Project Settings-ში), Vercel მას build-ის შედეგად მიიჩნევს. გამოსავალი: წაშალეთ — „Other" preset თავისით ემსახურება `public/`-ს.

2. **Express-ის ავტომატური ამოცნობა.** თუ შეცდომაში ჩამოთვლილია `app.js`, `index.js`, `server.js`, `src/index.js` და ა.შ., ესე იგი Vercel-მა პროექტი **Express**-ად ჩათვალა (რადგან `express` არის `dependencies`-ში) და სრულ Node სერვერს ეძებს. ჩვენთან `express` მხოლოდ ლოკალური გაშვებისთვისაა.

   გამოსავალი — `vercel.json`-ში:

   ```json
   { "framework": null }
   ```

   `null` ნიშნავს „Other"-ს და აუქმებს ავტომატურ ამოცნობას. თუ Project Settings-ში Framework Preset უკვე შენახულია როგორც „Express", შეცვალეთ **Other**-ით და გააკეთეთ **Redeploy**.

**შენიშვნა:** Vercel-ის serverless ინსტანციები დროებითია, ამიტომ `api/check.js`-ის rate limiter მხოლოდ ერთი „თბილი" ინსტანციის ფარგლებში მუშაობს. მკაცრი გლობალური ლიმიტისთვის დაგჭირდებათ საერთო საცავი (Vercel KV ან Upstash Redis).

### სხვა ვარიანტები

- **Render.com / Railway.app / Fly.io** — იქ `server.js` პირდაპირ გაეშვება (`npm start`); გასაღები ისევ Environment Variables პანელში ჩაიწერება.

ყველა შემთხვევაში წესი ერთია: **გასაღები არასდროს შედის კოდში ან git history-ში — ის ყოველთვის ცალკე, ჰოსტინგის საიდუმლო (secret) ცვლადების სისტემაში იწერება.**
